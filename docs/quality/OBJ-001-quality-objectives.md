## 1. Purpose

To set measurable objectives for the things the quality policy commits to, so that performance is judged against numbers rather than impressions.

Satisfies ISO 9001:2015 clauses 6.2.1, 6.2.2 and 9.1.1.

## 2. How these were chosen

Each objective is:

- **Consistent with the quality policy** — it measures something POL-001 commits to
- **Measurable** — it produces a number, from a source that already exists
- **Monitored** — it is reported at every management review
- **Relevant to the client** — it measures something a client would notice

Five objectives. Fewer would not cover the policy; more would not be tracked honestly.

## 3. Objectives

### OBJ-1 — Deliver on the agreed date

| | |
|---|---|
| **Measure** | Projects handed over on or before the date agreed in the scope agreement, as a percentage of projects handed over in the period |
| **Target** | ≥ 90% *[confirm]* |
| **Source of data** | Project records — agreed date vs handover date |
| **Who** | Owner |
| **Reviewed** | Quarterly |
| **Action if missed** | Every late project gets a recorded reason. Two with the same reason raises a corrective action |

### OBJ-2 — Do not let defects reach the client

| | |
|---|---|
| **Measure** | Nonconformities recorded in NCR-001 with "Reached client" = yes, per project handed over |
| **Target** | ≤ 1 per project *[confirm]* |
| **Source of data** | NCR-001 register |
| **Who** | Owner |
| **Reviewed** | Quarterly |
| **Action if missed** | Corrective action raised. The verification step in SOP-DES-001 §7.2 is examined first |

This is the most important of the five. It measures whether the design controls actually work.

### OBJ-3 — Quote accurately

| | |
|---|---|
| **Measure** | Projects where the final invoiced amount is within 10% of the accepted quote, as a percentage |
| **Target** | ≥ 80% *[confirm]* |
| **Source of data** | D1 — quotes and invoices |
| **Who** | Owner |
| **Reviewed** | Quarterly |
| **Action if missed** | Examine whether the overrun was scope change (acceptable, and should have been quoted under SOP-DES-001 §10) or a missed requirement at intake (a failure of SOP-CLI-001) |

The distinction in the action row is the whole value of this objective. An overrun from an agreed change is fine; an overrun from something missed at intake is a process failure.

### OBJ-4 — Clients are satisfied

| | |
|---|---|
| **Measure** | Average client satisfaction score from the post-handover feedback request |
| **Target** | ≥ 4 out of 5, with no individual response below 3 *[confirm scale]* |
| **Source of data** | FDB-001 register |
| **Who** | Owner |
| **Reviewed** | Quarterly |
| **Action if missed** | Any response below 3 is contacted directly and the reason recorded |

Requires the feedback request to actually be sent. Response rate is reported alongside the score — an average of 5 from one response out of eight projects is not evidence of anything.

### OBJ-5 — The management system is operated, not just written

| | |
|---|---|
| **Measure** | Scheduled QMS activities completed on time: quarterly management review, quarterly recovery test, six-monthly access review, annual internal audit |
| **Target** | 100% |
| **Source of data** | The registers themselves |
| **Who** | Owner |
| **Reviewed** | Quarterly |
| **Action if missed** | Rescheduled within 30 days and the reason recorded |

Included because the failure mode for a one-person QMS is not doing the work badly — it is not doing it at all, while client work takes priority. This objective makes that visible.

## 6. A note on small numbers

With a small number of projects per quarter, a single bad project moves a percentage a long way. Percentages are therefore reported with the underlying counts — "3 of 4 (75%)" rather than "75%" — so the review can judge whether a miss is a trend or one event.
